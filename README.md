# Growa Homecare (โกรว่า โฮมแคร์)

เว็บแอปพลิเคชันสำหรับอุปกรณ์มือถือ เพื่อช่วยครอบครัวไทยดูแลยาของผู้สูงอายุหรือคนที่กินยาประจำ ออกแบบเน้นความง่ายในการใช้งาน ตัวอักษรขนาดใหญ่อ่านง่าย คอนทราสต์สูง และไม่ใช้คำศัพท์ทางการแพทย์ที่เข้าใจยาก

---

## สแต็กเทคโนโลยี
- **Framework:** React 18 + Vite + TypeScript
- **Styling:** Tailwind CSS (Custom Design Tokens เพื่อผู้สูงอายุ)
- **Routing:** React Router DOM (v6)
- **Font:** IBM Plex Sans Thai (Google Fonts)
- **Data & State:** React State + แคชในเครื่อง (`localStorage`/IndexedDB) ซิงก์กับ **Supabase** (Auth, Postgres, Realtime, Storage)

---

## ข้อกำหนดการออกแบบ (Design Tokens)
- **สีหลัก (Primary):** สีส้มอิฐอบอุ่น (`#EA580C` / Orange 600) สบายตาและสังเกตง่าย
- **ขนาดตัวอักษร:** เริ่มต้นที่ `18px` (base) ขึ้นไป เพื่อให้อ่านสบายตา
- **ขนาดปุ่มและจุดสัมผัส:** ความสูงขั้นต่ำ `48px` (ตามมาตรฐานการเข้าถึง WCAG / Touch Target)
- **คอนทราสต์:** ใช้สีพื้นหลังขาว/เทาอ่อนมาก ตัดกับตัวอักษรสีเทาเข้มเกือบดำ (`#0F172A`)

## เชื่อมต่อฐานข้อมูลจริง (Supabase)

ถ้าไม่ตั้งค่าตามนี้ แอปจะทำงานแบบต้นแบบเดิม (ข้อมูลอยู่ในเครื่อง + ปุ่ม Demo)

1. สร้างโปรเจกต์ที่ [supabase.com](https://supabase.com)
2. เปิด **SQL Editor** วางไฟล์ `supabase/schema.sql` ทั้งไฟล์แล้วกด Run (สร้างตาราง สิทธิ์ ฟังก์ชัน และที่เก็บไฟล์)
3. **Authentication > Providers**: เปิด Email (และ Google ถ้าต้องการ) แล้วเพิ่ม URL ของเว็บใน **Authentication > URL Configuration**
4. คัดลอก `.env.example` เป็น `.env` แล้วใส่ `VITE_SUPABASE_URL` และ `VITE_SUPABASE_ANON_KEY` (**Project Settings > API** ใช้ anon key เท่านั้น)
5. บน Vercel ให้ตั้งตัวแปรสองตัวเดียวกันใน Environment Variables

### ข้อมูลทำงานอย่างไร
- สมัคร/เข้าสู่ระบบจริงด้วยอีเมลหรือ Google, สร้างบ้านหรือเข้าร่วมด้วยรหัสเชิญ 8 หลัก, เจ้าของบ้านมอบบทบาท/นำสมาชิกออกได้
- ปฏิทิน บันทึกอาการ คำขออนุญาต ข้อมูลสมาชิก เก็บเป็นรายการในตาราง `home_items` (คนในบ้านเห็นตรงกันแบบเรียลไทม์)
- ตู้ยา ประวัติกินยา การตั้งค่า และข้อมูลสุขภาพพื้นฐาน เก็บเป็นของแต่ละบัญชีใน `user_docs`
- ไฟล์แนบ (รูปยา เอกสาร) เก็บใน Storage bucket `attachments` แยกตามบ้าน
- ใช้งานออฟไลน์ได้ ข้อมูลที่ค้างจะส่งขึ้นเซิร์ฟเวอร์เมื่อกลับมาออนไลน์

### ข้อจำกัดที่ควรรู้
- การซ่อนข้อมูลสุขภาพ/ขออนุญาตดู-แก้ไข (หน้าความเป็นส่วนตัว) บังคับใช้ที่ฝั่งแอป ยังไม่ได้บังคับที่ฐานข้อมูล สมาชิกในบ้านเดียวกันที่เขียนคำสั่งเองยังอ่านข้อมูลของกันได้
- การแก้ตารางยาของสมาชิกคนอื่นจะไม่ไปเปลี่ยนตู้ยาของเจ้าตัว (ตู้ยาเป็นของเจ้าของบัญชี)
- ข้อมูลร้านยาใน `src/lib/config.ts` เป็นค่าตัวอย่าง ต้องแก้เป็นร้านจริงก่อนเปิดใช้งาน

## ระบบปรึกษา (Smart Consultation)

เส้นทาง: `/consult` (ผู้ใช้) และ `/pharmacist` (เภสัชกร/คลินิก) โค้ดอยู่ที่ `src/consult/`, `src/pages/consult/`, `src/pages/pharmacist/`

### โหมดการทำงาน
- `VITE_CONSULT_BACKEND=mock` (ค่าเริ่มต้น): โหมดทดสอบ ข้อมูลอยู่ในเครื่อง ผู้ให้บริการเป็นตัวอย่าง ทุกหน้าแสดงป้ายโหมดทดสอบ ไม่มีการตอบกลับอัตโนมัติ ทดลองฝั่งเภสัชกรได้ที่ `/pharmacist`
- `VITE_CONSULT_BACKEND=supabase`: ใช้งานจริง ต้องทำขั้นตอนด้านล่างก่อน

### เปิดใช้งานจริง
1. รันใน SQL Editor ตามลำดับ: `supabase/consult_schema.sql`, `supabase/consult_v2.sql`, `supabase/consult_v3.sql` แล้ว `supabase/consult_v4.sql` และ `supabase/consult_v5.sql` (ไม่แตะตารางเดิมของแอป รันซ้ำได้ v3 ย้ายค่า `active` เดิมของผู้ให้บริการไปเป็นสถานะ แล้วลบคอลัมน์ `active` ส่วน v4 เพิ่มหมวดหมู่ที่เพิ่มเองได้ การรับเรื่องแบบจองเคสสำหรับทีมงานหลายคน และรีวิว ส่วน v5 เปิดช่องสัญญาณโทรแบบ private ให้เฉพาะผู้ป่วยกับผู้ดูแลเคส)
2. ตั้งแอดมินคนแรกใน SQL Editor (ตั้งจากในแอปไม่ได้โดยออกแบบ):
   ```sql
   insert into public.consult_staff (user_id, role)
   select id, 'admin' from auth.users where lower(email) = lower('<อีเมลแอดมิน>');
   ```
3. เข้า `/admin` เพิ่มผู้ให้บริการและผูกบัญชีเภสัชกร (ตรวจใบอนุญาตก่อน) เภสัชกรใช้งานที่ `/pharmacist`
   - หน้าแอดมินเป็นการ์ดของแต่ละร้านแบบเดียวกับที่ผู้ใช้เห็น กดเข้าไปดูรายละเอียดและแก้ไขได้ และเห็นสถานะร้านกับออนไลน์/ออฟไลน์
   - ข้อมูลร้าน: รูป (อัปโหลดไฟล์ ย่อเป็นสี่เหลี่ยมแล้วเก็บในแถวของร้าน) แนะนำตัว ที่ตั้ง ลิงก์แผนที่ เบอร์ LINE อีเมล เว็บไซต์ เวลาทำการ
   - สถานะร้าน: เปิด / ปิดชั่วคราว (ผู้ใช้ไม่เห็น การปรึกษาที่เปิดอยู่ยังคุยต่อได้) / แบน (ยกเลิกการปรึกษาที่ค้างทั้งหมด ทีมงานเข้าไม่ได้) เปิดกลับได้ทุกเมื่อ
   - ลบร้านได้เฉพาะร้านที่ไม่มีประวัติการปรึกษา ถ้ามีแล้วต้องแบนแทน เพื่อไม่ให้ประวัติของผู้ป่วยขาดหาย
   - ทีมงานร้านละไม่เกิน 5 คน ผูกด้วยอีเมลพร้อมเบอร์โทร (อีเมลต้องเป็นบัญชีที่สมัครแล้ว) กดปุ่มบวกเพื่อเพิ่มทีละหลายคน แก้เบอร์ภายหลังได้
   - ไม่มีข้อมูลสุขภาพของผู้ใช้ในหน้าแอดมินเลย
   - หมวดหมู่ผู้ให้บริการเลือกจากรายการ หรือเลือก “อื่นๆ” แล้วพิมพ์ชื่อหมวดใหม่ได้ (เช่น ทันตกรรม) ผู้ใช้เห็นร้านแยกกลุ่มตามหมวด
   - ผู้ใช้กด “ดูรายละเอียด” ที่การ์ดแล้วเห็นข้อมูลชุดเดียวกับที่แอดมินเห็น พร้อมคะแนนและรีวิว
   - รีวิว: ให้ดาว 1-5 และความคิดเห็นได้หลังการปรึกษาเสร็จเท่านั้น แสดงแบบไม่ระบุชื่อ แก้ไขได้ คะแนนร้านคำนวณจากรีวิวจริงเท่านั้น แอดมินลบรีวิวที่ไม่เหมาะสมได้
   - ทีมงานหลายคนในร้านเดียวกันใช้คิวเดียวกัน: รับเรื่อง = จองเคส คนแรกที่กดได้ คนอื่นรับซ้ำไม่ได้ เปิดข้อมูลสุขภาพ ตอบแชท เขียนและปิดบันทึกได้เฉพาะผู้ดูแลเคส คืนเคสเข้าคิวหรือรับช่วงต่อได้ (ระบบบันทึกไว้ในประวัติการเข้าถึงที่ผู้ป่วยเห็น)
4. ตั้ง `VITE_CONSULT_BACKEND=supabase` ใน `.env` และ Vercel แล้ว deploy ใหม่

### แจ้งเตือนนัดติดตาม (Web Push)
Edge Function `consult-followup-reminders` รันทุกวัน 09:00 น. ไทย ส่งแจ้งเตือนนัดที่ถึงกำหนดและยังไม่เคยเตือน ข้อความไม่มีข้อมูลสุขภาพ
1. สร้างกุญแจ: `deno run supabase/functions/consult-followup-reminders/generate_keys.ts`
2. ตั้ง Edge Function secret `VAPID_KEYS_JSON` (กุญแจส่วนตัว ห้าม commit) และ `VAPID_SUBJECT` (เช่น `mailto:อีเมลติดต่อ`)
3. ตั้ง `VITE_VAPID_PUBLIC_KEY` ใน `.env` และ Vercel
4. deploy function แล้วรัน `supabase/consult_push_cron.sql` (แทนค่า `<project-ref>`)

ผู้ใช้เปิดการแจ้งเตือนได้ที่หน้าประวัติการปรึกษา บน iPhone ต้องเพิ่มเว็บลงหน้าจอโฮมก่อน

### ลบข้อมูลตามคำขอ
หน้าประวัติมีปุ่มลบรายการและลบทั้งหมด ลบได้เมื่อการปรึกษาปิดแล้ว รวมข้อความ ไฟล์แนบ และบันทึกของผู้ให้บริการ ตาราง `consult_erasure_log` เก็บแค่ว่ามีการลบเมื่อไร ปุ่มนี้ไม่รวมข้อมูลสุขภาพ ตู้ยา และบัญชี

### สิ่งที่ต้องทำก่อนเปิดให้ผู้ป่วยจริงใช้
- **แอปไม่ประเมินอาการ:** ระบบรับอาการส่งให้ผู้ให้บริการอ่านเท่านั้น ไม่มีการคัดกรองอาการฉุกเฉิน ควรให้เภสัชกรตรวจตัวเลือกอาการใน `src/data/consultReference.ts`
- **PDPA:** ให้ฝ่ายกฎหมายตรวจข้อความยินยอม และการที่ผู้ใช้ลบบันทึกของเภสัชกรได้ ซึ่งอาจขัดกับหน้าที่เก็บเวชระเบียน
- **โฟลเดอร์เอกสาร (`/folders`):** เก็บผลตรวจ ใบสั่งยา ใบรับรองแพทย์ รูปอาการ และไฟล์อื่น ๆ แยกเป็นโฟลเดอร์ ตั้งชื่อ สี และระบุว่าเกี่ยวกับใคร แต่ละเอกสารมีชื่อ ชนิด วันที่ โน้ต ค้นหาและกรองตามชนิดได้ รายละเอียดซิงก์ข้ามอุปกรณ์ผ่านตาราง `user_docs` เดิม (ไม่ต้องรัน SQL เพิ่ม) ส่วนตัวไฟล์ใช้ที่เก็บไฟล์เดิมของแอป ตอนปรึกษาเลือก "เลือกจากโฟลเดอร์" ได้ทั้งในแบบสอบถามและในแชท ระบบทำสำเนารูป/PDF ไปส่ง ต้นฉบับไม่เปลี่ยน ข้อควรระวัง: ไฟล์ในโฟลเดอร์อยู่ในที่เก็บไฟล์ของบ้านเหมือนไฟล์ในข้อมูลสุขภาพ จึงอาจถูกอ่านได้โดยสมาชิกบ้านที่รู้รหัสไฟล์ (รหัสสุ่ม ไม่แสดงในแอป)
- **โทรเสียงและวิดีโอคอล:** เป็น WebRTC จริง เสียงและภาพวิ่งตรงระหว่างสองเบราว์เซอร์ ส่งสัญญาณนัดหมายผ่าน Supabase Realtime ช่อง private (ต้องรัน `consult_v5.sql`) โทรได้เมื่อเคสกำลังปรึกษา ผู้รับเห็นแบนเนอร์รับสายในหน้าเคส ผลการโทรบันทึกลงแชท เครือข่ายที่เข้มงวดต้องตั้ง TURN (`VITE_TURN_*` ใน .env.example) โหมดทดสอบโทรได้จริงระหว่างสองแท็บของเบราว์เซอร์เดียวกัน ยังไม่มีแจ้งเตือนสายที่ไม่ได้รับเมื่อปิดหน้าเว็บอยู่
- **นัดหมาย:** พักไว้ก่อน เปิดกลับได้ที่ `appointmentsEnabled` ใน `src/consult/calls.ts`
- **ความยินยอม:** ทุกการปรึกษาส่งข้อมูลสุขภาพและอาการล่าสุดครบทุกหมวด ผู้ใช้เลือกปิดบางหมวดไม่ได้ ให้ฝ่ายกฎหมายตรวจเรื่องนี้ด้วย

## นโยบายความปลอดภัยและความเป็นส่วนตัว
- ไม่มี Token หรือ Secret ในโค้ด ใช้เฉพาะ anon key ที่เปิดเผยฝั่งเบราว์เซอร์ได้ โดยความปลอดภัยพึ่ง Row Level Security ใน `supabase/schema.sql`
- ห้ามใส่ service_role key ในโปรเจกต์นี้ และไม่ commit ไฟล์ `.env`
