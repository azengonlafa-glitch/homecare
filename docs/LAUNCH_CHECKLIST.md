# Growa Homecare: งานที่เหลือก่อนเปิดให้คนจริงใช้

อัปเดตล่าสุด 13 พ.ย. 2569 · เว็บจริง https://homecare1-one.vercel.app (main ล่าสุด `06f52fe`)

สถานะตอนนี้: ใช้เป็นเดโมหรือทดสอบในครอบครัวได้ **ยังไม่ควรเปิดให้คนนอกครอบครัวใช้กับข้อมูลสุขภาพจริง** จนกว่าจะทำข้อ 1 เสร็จ

---

## 1. ต้องทำก่อนเปิดจริง (สำคัญที่สุด)

### 1.1 ซ่อนข้อมูลสุขภาพจากคนในบ้านให้ฐานข้อมูลบังคับจริง: โค้ดเสร็จแล้ว รอรัน SQL
- ทำแล้ว (13 พ.ย. 2569): แยกข้อมูลสมาชิกเป็นส่วนที่ทุกคนในบ้านเห็น (`member_records`) กับส่วนสุขภาพ (`member_health`) ฐานข้อมูลส่งส่วนสุขภาพให้เฉพาะเจ้าของ คนที่เจ้าของเปิดแชร์ คนที่ได้รับอนุญาตให้ดู และคนที่มีสิทธิ์แก้ คนที่ถูกห้ามแก้ไม่ได้เด็ดขาด ค่าความเป็นส่วนตัวเปลี่ยนได้เฉพาะเจ้าของ คำขออนุญาตอนุมัติได้เฉพาะเจ้าของข้อมูล
- บันทึกอาการ (journal) ยังให้ทุกคนในบ้านเห็นเหมือนเดิม (ตัดสินใจแล้ว)
- ทดสอบแล้ว: ฐานข้อมูลจำลอง 20 กรณี และเปิดเบราว์เซอร์จำลองเซิร์ฟเวอร์ (คนที่ปิดแชร์ขึ้นว่าซ่อน แอปไม่ส่งข้อมูลสุขภาพของคนอื่นขึ้นไปทับ)
- เหลือ: merge แล้วรอเว็บขึ้น จากนั้นรัน `supabase/health_privacy.sql` (ข้อ 1.2)

### 1.2 รัน SQL ที่ค้างอยู่บนเซิร์ฟเวอร์ (หน้า SQL Editor ของ Supabase) ตามลำดับ
- [ ] `supabase/account_delete.sql` (ไม่รัน = ปุ่มลบบัญชีใช้ไม่ได้)
- [ ] `supabase/hardening.sql` (จำกัดการเดารหัสเชิญเข้าบ้าน 10 ครั้ง/15 นาที และไฟล์แนบไม่เกิน 20 MB)
- [ ] `supabase/health_privacy.sql` **หลังเว็บเวอร์ชันใหม่ขึ้นแล้วเท่านั้น** (ย้ายข้อมูลเดิมและเปิดการซ่อนข้อมูลจริง รันซ้ำได้)
- [ ] `supabase/data_access_log.sql` **หลัง health_privacy.sql** (บันทึกว่าใครเข้าดู/แก้ข้อมูลสุขภาพของฉัน ไม่รัน = หน้าตั้งค่าจะบอกว่ายังดูบันทึกไม่ได้ ไม่กระทบอย่างอื่น)
- [ ] เปลี่ยนการเช็คเวลากินยาเป็นทุก 1 นาที (ดูข้อ 4)

### 1.3 ตั้งค่าใน Supabase Dashboard
- [ ] Authentication → เปิด Leaked password protection (เช็ครหัสผ่านที่เคยรั่ว)

### 1.4 ล้างข้อมูลทดสอบบนเซิร์ฟเวอร์จริง
- [ ] ผู้ใช้ทดสอบ (ตอนตรวจมี 22 บัญชี) บ้าน 12 หลัง ห้องปรึกษา 30 ห้อง บัญชีเจ้าหน้าที่ทดสอบ 2 บัญชี
- Claude ทำรายการให้ดูก่อน แล้วลบเมื่อคุณสั่งเท่านั้น

### 1.5 เรื่องกฎหมาย (ต้องให้ผู้รู้ตรวจ)
- [ ] ส่ง `docs/CONSENT_SHARING_EDITING_DRAFT.md` ให้ผู้รู้กฎหมาย: เอกสารความยินยอมไม่ได้พูดถึงการให้คนอื่น "แก้ไข" ข้อมูล มีร่างข้อความและ 5 คำถามที่ต้องตัดสิน
- [ ] เอกสารความยินยอมยังเป็นร่าง `draft-0.3`: เติมชื่อ/ช่องทางติดต่อผู้ควบคุมข้อมูล, DPO, ที่ตั้งเซิร์ฟเวอร์ (`CONTROLLER_CONTACT`, `DATA_LOCATION_NOTE` ใน `src/data/consentDocument.ts`)
- [ ] เขียนข้อกำหนดการใช้งาน (ช่องติ๊กตอนสมัครพูดถึงแต่ยังไม่มีเอกสาร)
- [ ] เภสัชกร/ผู้รู้กฎหมายตัดสินข้อความแนวคำแนะนำยา: ช่อง "ใช้รักษาอะไร" (`purpose` ใน `src/data/drugDb.ts`), ก่อน/หลังอาหารที่กรอกให้อัตโนมัติ (`meal`), รายละเอียดยา 4 ตัวจาก NHS (`src/data/drugDetails.ts`)

## 2. ก่อนเปิดระบบปรึกษาเภสัชกรจริง
- [ ] ข้อมูลเภสัชกร/ร้านยาจริงและเลขใบอนุญาต
- [ ] ตั้ง `VITE_CONSULT_BACKEND=supabase` ใน Vercel (ตั้งตอนจะเปิดจริงเท่านั้น)
- [ ] ทดสอบโทรข้ามเครือข่ายจริง (เช่น โทรศัพท์ใช้ 4G กับคอมใช้ Wi-Fi) ถ้าต่อไม่ติดต้องมีเซิร์ฟเวอร์ TURN (`VITE_TURN_*`)

## 4. แจ้งเตือนกินยา: เปลี่ยนจากทุก 5 นาทีเป็นทุก 1 นาที
ในโค้ดแก้แล้ว (`supabase/med_push.sql`) บนเซิร์ฟเวอร์ต้องรันบรรทัดนี้ใน SQL Editor:

```sql
select cron.alter_job((select jobid from cron.job where jobname = 'med-dose-reminders'), schedule := '* * * * *');
```

ผล: แจ้งเตือนเด้งช้าสุดประมาณ 1 นาทีหลังถึงเวลา (เดิมช้าสุด 5 นาที) เซิร์ฟเวอร์ถูกเรียกวันละ 1,440 ครั้ง (เดิม 288) ยังอยู่ในโควตาฟรีของ Supabase (500,000 ครั้ง/เดือน)
